How DKIM keys support verification

DNS supplies the public key; the message supplies the signature.

A sending system signs selected headers and a canonicalized message body using a private key. Its DKIM-Signature header identifies a signing domain with d= and a selector with s=. A verifier retrieves the public key at selector._domainkey.domain and verifies the message.

This page performs the DNS/key part of that workflow. It can identify a key record and configuration concerns, but it does not have the message needed for cryptographic verification. A decoded key is not evidence of a verified signature or a trusted sender.

SELECTOR

The header's s= value chooses a key and supports rotation between selectors.

PUBLIC KEY

The record's p= value holds the key. An empty p= revokes that selector's key.

KEY SIZE

RSA modulus size and Ed25519 encoded key size describe different algorithms.

References: DKIM specification · RSA and hash guidance · Ed25519 for DKIM.

Check a selector in four steps

Use actual signing details for the most useful result.

  1. Find d= and s= in a sent message

    Take the domain and selector from the same DKIM-Signature header.

  2. Choose the lookup scope

    Use that selector, optionally adding the short common-selector list.

  3. Inspect the key and DNS answer

    Review aliases, the p= value, key size, flags and any malformed tags.

  4. Verify the message separately

    Use a message verifier to check the signature, then evaluate DMARC alignment and other delivery factors.
