school

One alias, fewer repeated arguments

Give your SSH client the connection settings it should reuse.

A Host block groups client settings for an alias or matching pattern. HostName supplies the actual destination, User selects the account and Port selects the service port. For example, a block named production can let you type ssh production instead of repeating its hostname, user, port and identity path.

Other tools can use the same settings when they invoke OpenSSH. The resulting behavior still depends on the client, matching blocks, command-line overrides and any existing configuration. Keep specific entries near the beginning and broad defaults near the end.

IDENTITYFILE

A path to the client’s identity file. It does not install or upload a key.

PROXYJUMP

A route through one or more jump hosts before the final destination.

SERVERALIVEINTERVAL

The time between SSH keepalive probes when the option is enabled.

Reference: OpenSSH client configuration manual.

Build and install in five steps

Prepare the file, then review it on the client where you will use it.

  1. Name your connection

    Set an alias and the destination hostname or IP address.

  2. Choose the account and identity

    Add the user, service port and optional private-key path.

  3. Configure advanced behavior

    Use keepalives, proxy routing and forwards only where needed.

  4. Add and order your hosts

    Keep specific blocks before broad patterns. Check the live preview.

  5. Review, merge and save

    Copy or download config, merge existing settings and apply appropriate file permissions before using it.
