What PEM formatting does

A readable text envelope around binary data.

A PEM block has a BEGIN label, a Base64 body and a matching END label. Depending on its label, the body can hold a certificate, certificate request, public key, private key or another encoded object. The formatter checks that envelope and Base64, then rebuilds the text using your options.

The object inside is left intact. Rewrapping a public certificate does not change its binary fingerprint. Rewrapping a private-key block does not turn it into a public key, decrypt it or make it suitable for another key container.

PEM

Text boundaries plus Base64. Standard output uses 64-character body lines.

DER

A binary encoding often carried inside PEM. This tool does not validate its structure.

PPK

PuTTY's distinct private-key container. PEM line wrapping is not a PPK conversion.

References: PEM textual encoding · Historical PEM headers.

Format in four steps

Review the input, then choose the output your application expects.

  1. Paste text or choose a file

    Supply complete PEM blocks, including matching boundary lines and any supported encryption headers.

  2. Choose line wrapping and endings

    Start with 64 characters and LF unless your destination requires something else.

  3. Format and review the block list

    Check the labels and decoded byte counts. No certificate trust or key validity check is performed.

  4. Copy or save the PEM

    Use the result in the intended application. Clear the page when finished.
