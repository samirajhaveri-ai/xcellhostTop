school

Read the claims. Keep verification separate.

A compact signed JWT contains three encoded segments.

The header describes how a token claims to be protected. The payload carries statements such as an issuer, subject or expiration time. The final segment contains the signature or MAC bytes, except for an explicitly unsecured token.

Header

Review parameters such as alg, typ and kid. Treat them as input supplied by the token.

Payload

Read registered and custom claims. A value’s presence does not prove its origin or accuracy.

Signature

Verification needs appropriate trusted keys and application policy. This page only decodes and displays bytes.

checklist

Inspect a token in four steps

Start with the structure, then review the claims.

  1. Paste a complete token

    Use a three-part compact JWT. A Bearer prefix is optional.

  2. Decode and read the header

    Inspect the declared algorithm and formatted JSON.

  3. Review claims and time boundaries

    Look at issuer, subject, audience, expiry and custom fields. Read any inspection notes.

  4. Copy or save your inspection

    Export the decoded report with its unverified status and comparison time.
