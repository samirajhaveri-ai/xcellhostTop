How a certificate fingerprint works

A short identifier for a complete certificate.

A certificate fingerprint is a digest of the certificate's binary encoding. PEM is a text wrapper around those bytes, so this tool decodes that wrapper before calculating the fingerprints. Renaming a certificate file or rewrapping its PEM lines leaves the result unchanged.

A renewed certificate usually has different encoded fields and a different fingerprint, even if the same public key is reused. Compare the entire value using the same hash algorithm. SHA-256 is a practical default; MD5 and SHA-1 remain here for compatibility with older displays.

CERTIFICATE

Fingerprints on this page cover the complete certificate, including its signature.

PUBLIC KEY

A public-key-only fingerprint covers different bytes and will not match this result.

SSH HOST KEY

OpenSSH fingerprints use a different key encoding. Use the separate SSH tool.

References: PEM certificate encoding · X.509 certificate structure.

Compare in four steps

Keep the input and expected value aligned.

  1. Choose the public certificate

    Paste one CERTIFICATE block or choose its PEM/DER file. Keep private keys separate.

  2. Select the preferred algorithm

    Use the algorithm shown by the source you are comparing against.

  3. Calculate and review

    Check the subject and issuer to confirm you supplied the intended certificate.

  4. Compare through a trusted source

    Copy a fingerprint or paste the expected hexadecimal value into the comparison field.
