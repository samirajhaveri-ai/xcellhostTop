school

One pair, two different jobs

Your public key is installed on the destination. Your private key stays with you.

SSH public-key authentication lets a client prove it holds a private key by signing data for a connection. The server checks the signature against an authorized public key. Generating the pair prepares your credentials; the destination account must still authorize the public half.

publicPublic key

The .pub file is one line for authorized_keys or your Git account.

lockPrivate key

A credential to keep on your client, protected with a passphrase and file permissions.

fingerprintFingerprint

A short identifier for comparing copies of the public key.

These formats wrap the same underlying pair. A comment labels the key, and a passphrase protects its saved private files. Neither changes which public key the server authorizes.

Format references: OpenSSH private keys · PuTTY PPK format · Web Crypto generation.

From generation to your first login

Prepare, save and install the correct half.

5 STEPS
  1. Choose an algorithm

    Match the server or Git host’s supported algorithms. Set a curve or RSA size if needed.

  2. Label and protect it

    Add an optional comment, then enter and confirm a unique passphrase.

  3. Generate and compare

    Generate a fresh pair locally and note its SHA-256 fingerprint.

  4. Save both files

    Choose a base filename. Download .pub and a compatible private format. On Unix-like systems, restrict the private file to mode 600.

  5. Authorize the public key

    Install only the public line in authorized_keys or your Git account, then test with the matching private key.
