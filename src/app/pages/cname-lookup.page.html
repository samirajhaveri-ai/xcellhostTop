info

A name pointing to another name

Understand the DNS step between an alias and its address.

A CNAME tells DNS clients that a name is an alias. For example, www.example.com might point to site.hosting.example.net, letting the hosting service manage the destination addresses. More than one alias can appear along that path.

This page asks your chosen resolver for each step, then optionally queries A and AAAA at the endpoint. It keeps the actual responses so you can distinguish an empty answer from a missing name or a resolver error. DNS aliases do not change the URL in a browser.

ILLUSTRATIVE DNS PATHwww.example.comarrow_forwardsite.hosting.example.netCNAME · hostname to hostname

ALIAS

The name where the CNAME record is published.

CANONICAL TARGET

The hostname named by the alias. It may itself be another alias.

TTL

The remaining cache lifetime in a resolver answer, expressed in seconds.

Read more: DNS aliases in RFC 1034 · DNS record types

checklist

Inspect an alias in four steps

Begin with the exact name you want to troubleshoot.

  1. Enter your hostname

    Use a subdomain such as www.example.com, or paste its website URL.

  2. Choose the query settings

    Pick Google Public DNS or Cloudflare and decide whether to check endpoint addresses.

  3. Review the chain

    Read each target, TTL and stopping reason. Expand the captured answers if a value looks unexpected.

  4. Compare and share

    Check the trace against your provider settings, copy a target or export a PDF, CSV or JSON report.
