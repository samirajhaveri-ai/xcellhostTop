    Overview

    Every cloud has its own router. You need one that talks to all of them.

    AWS, Azure, Google Cloud and Oracle each give you a routing service inside their own network — and each stops at the edge of that network. Once you run workloads in two clouds, an office or two and a rack in a data centre, someone has to decide which prefix goes where, what happens when a link drops and which environment may talk to which. Done with hand-edited static routes, that turns into outages after every change.

    XcellHost Cloud Router is a managed virtual router hosted in our Mumbai Tier IV data centre. It peers over BGP with each cloud's own routing service and with your on-premises routers, carries static routes where BGP isn't available, separates environments in VRFs and filters every route it learns. Our engineers design the routing policy with you, deploy it and watch it 24×7 from the NOC.

    Capabilities

    What the router does — and what each cloud calls its half.

    The cloud providers use different names for similar jobs. Pick one to see what it does and how XcellHost Cloud Router connects to it.

    eBGP and iBGP

    Dynamic routing with each cloud and your sites; private ASNs planned for you.

    Static routes

    For devices and links that can't run BGP, with tracking so dead routes are pulled.

    VRFs

    Separate routing tables for prod, dev, partners or subsidiaries on one router.

    Route policy

    Prefix lists, communities, local-preference and AS-path prepend to steer traffic.

    BFD & failover

    Fast failure detection where the peer supports it; backup paths pre-installed.

    IPv4 + IPv6

    Dual-stack sessions where the cloud side supports IPv6 peering.

    Overlap handling

    NAT or VRF separation when two networks use the same address range.

    HA pair

    Two router instances with separate paths so one failure doesn't stop routing.

    Transit GatewayDirect Connect gatewaySite-to-Site VPN

    AWS Transit Gateway is AWS's transit hub for VPCs and on-premises networks. Per AWS, it takes VPC, VPN, Direct Connect gateway, Connect (SD-WAN appliance) and peering attachments, each associated with a transit gateway route table; VPN and Direct Connect gateway attachments exchange routes with your router over BGP.

    How we connect: BGP from Cloud Router to a Direct Connect gateway over a Private Connect circuit, or to a Site-to-Site VPN as backup. TGW route tables stay in your AWS account.

    ExpressRoute gatewayRoute ServerVirtual WAN

    Azure connects private circuits through an ExpressRoute virtual network gateway. Azure Route Server, per Microsoft, is a managed service that exchanges routes over BGP between network virtual appliances and the virtual network, acting as a route reflector. Virtual WAN is Microsoft's hub-and-spoke option for larger estates.

    How we connect: BGP over an ExpressRoute circuit (private peering), or IPsec + BGP to a VPN gateway. Where you run an NVA in Azure, Route Server learns its routes.

    Cloud RouterHA VPNNetwork Connectivity Center

    Google Cloud Router, per Google, is a fully managed service that runs BGP sessions and turns learned routes into dynamic routes in your VPC — it doesn't forward packets itself. Dedicated and Partner Interconnect VLAN attachments and HA VPN require it; it supports custom route advertisements, BFD and MD5 authentication.

    How we connect: our router peers with your Google Cloud Router over a Partner or Dedicated Interconnect VLAN attachment, or over HA VPN tunnels.

    Dynamic Routing GatewayFastConnectSite-to-Site VPN

    On Oracle Cloud Infrastructure, private circuits and VPNs attach to a Dynamic Routing Gateway (DRG), which routes between your VCNs and on-premises networks. FastConnect private peering uses BGP between your edge and Oracle.

    How we connect: BGP over a FastConnect virtual circuit in Mumbai or Hyderabad through a partner, or IPsec VPN to the DRG. See Oracle Cloud.

    Use cases by industry

    Same router, different routing problems.

    Core banking on-prem, analytics in the cloud

    Keep the core system and its data in India, send only approved datasets to a cloud analytics VRF, and log every route change for the auditor.

    • Separate VRFs for core, analytics and vendor access
    • Prefix lists so vendors see only their subnets
    • Route-change records kept for 180 days

    Plants, ERP and a cloud MES

    Plants on SD-WAN, ERP in a colocation rack and a cloud-hosted MES — with plant networks that often reuse the same 192.168.x.x range.

    • NAT or VRFs for overlapping plant subnets
    • Backup paths so a plant link cut doesn't stop dispatch
    • See Managed SD-WAN for the plant edge

    Hospital systems and cloud PACS

    Imaging archives move to the cloud while the HIS stays local; clinical and guest traffic must never mix.

    • Clinical, admin and guest VRFs
    • Imaging routes preferred over the private line
    • Routing that supports DPDP safeguards for patient data

    Multi-cloud SaaS with a customer-dedicated tier

    Run in two clouds, peer with large customers privately and keep staging away from production.

    • BGP to AWS and Google Cloud from one hub
    • A VRF per enterprise customer link
    • Route changes reviewed like code, applied in a window

    Stores, warehouses and a cloud storefront

    Hundreds of small sites, a payment network that must stay separate and a cloud storefront that peaks on sale days.

    • Card-payment traffic in its own VRF
    • Store routes summarised to keep tables small
    • Backup path pre-installed before sale events

    Campuses, labs and government cloud

    Several campuses, research labs that need cloud burst, and departments that must stay apart.

    • One VRF per department or campus
    • Cloud burst routes for labs only
    • XcellHost is MeitY empanelled

    CERT-In directions, April 2022

    CERT-In asks organisations to report specified cyber incidents within 6 hours of noticing them and to keep ICT system logs for 180 days within India. Cloud Router session, change and flow logs are kept in Mumbai for at least that period, ready to hand to your incident team.

    DPDP Act 2023

    Asks for reasonable security safeguards for personal data. VRF separation and filtered routes limit who can reach systems that hold it.

    RBI & SEBI

    Regulated entities face IT governance, network segmentation and outsourcing expectations. Route policies and change records support those reviews.
