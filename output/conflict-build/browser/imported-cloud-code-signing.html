Overview

Sign from wherever your team works — with code signing delivered as a service.

Code signing proves who published a file and that nobody changed it afterwards. Since June 2023 the CA/Browser Forum has required every code-signing private key to live in certified hardware — a FIPS 140-2 Level 2 or Common Criteria EAL4+ token or HSM. For a team spread across offices, laptops and build servers, a single USB token quickly becomes the bottleneck: it gets couriered, shared, plugged into one machine and forgotten in another.

Cloud code signing moves the key into a certified cloud HSM and lets your developers and pipelines sign through an API, from anywhere, under rules you set. Automated workflows handle high volumes, role-based access decides who may use which key, and every signing — successful or refused — is written to a detailed log. XcellHost supplies it on DigiCert or Sectigo, completes the OV or EV validation with you, connects it to your CI/CD and supports it 24×7 from Mumbai.

How it works

Connect, approve, sign — and the key never leaves the vault.

Your build sends a hash, not the key. The service checks policy, asks for approval where you want it, signs inside the HSM and hands back a signature.

01 · Connect
client API · KSP · PKCS#11

Connect your pipeline

A small signing client — or the platform's own tools such as SignTool and jarsigner — talks to the service with an API key and a client certificate.

  • GitHub, GitLab, Jenkins, Azure DevOps
  • Works with native signing tools
  • Secrets kept in your CI vault
02 · Approve & sign
key stays in HSM

Pass the policy, sign in the HSM

The request is checked against your rules — who, which key, which branch, which hours — and, if you require it, an approver confirms with MFA. Only the hash travels.

  • Role-based access per key
  • Multi-user approvals with MFA
  • Release windows
03 · Verify & audit
log every event

Timestamp, ship, keep the evidence

A trusted RFC 3161 timestamp keeps the signature valid after the certificate expires. Each event lands in the audit log you can export to your SIEM.

  • RFC 3161 timestamping
  • Searchable signing history
  • Audit-ready exports

Rules that shaped code signing
Three industry changes — and the Indian rules that sit beside them.
Why hardware-held keys are now the only option, and why automating the yearly certificate cycle matters from 2026.

    

      
      
June 2023Keys must live in hardware
CA/Browser Forum: new code-signing keys are generated and stored on a FIPS 140-2 Level 2 / CC EAL4+ token or HSM. Cloud HSMs qualify.

      
March 2024EV no longer skips SmartScreen
Microsoft stopped giving EV-signed files instant SmartScreen reputation. EV is still the highest assurance; reputation now builds with clean downloads.

      
February 2026One-year certificates
New code-signing orders are limited to one year of validity. HSM-based plans can run longer but reissue every year — in a cloud service, we schedule it for you.

    

    

      
CERT-InSBOMs & 6-hour reporting
CERT-In's 2022 directions require incidents to be reported within 6 hours and logs kept for 180 days; its 2024 SBOM guidelines ask software suppliers to know what they ship. Signing logs and SBOMs help with both.

      
DPDP Act 2023Reasonable security safeguards
Software that handles personal data should be provably genuine. Tampered updates are a classic route to a breach — and to penalties.

      
RBI · SEBISoftware integrity for regulated entities
RBI's IT governance Master Direction and SEBI's CSCRF expect controlled change and secure key management from banks, brokers and their software vendors.

      
MeitY · IT ActKnow which signature you need
Code signing proves a software publisher. Statutory e-signatures under the IT Act come from CCA-licensed CAs — we supply those separately.

    

    
Summaries for planning, not legal advice. Confirm how each rule applies to you with your compliance team.
