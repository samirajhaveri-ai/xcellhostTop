What Cloud HSM is

A hardware security module, delivered like a cloud service.

An HSM keeps keys inside tamper-resistant hardware and performs signing, encryption and key wrapping there. A cloud HSM is the same hardware run as a service: the provider installs, powers, patches and monitors the appliances, and you get a dedicated partition with its own keys, users and policy. You never touch a screwdriver, and the provider's staff never touch your keys.

XcellTrust Cloud HSM runs those partitions in our Mumbai Tier IV data centre, with a DR copy at a partner data centre*. Your applications connect over private connectivity or IPsec through our cloud router — from AWS, Azure, Google Cloud, Oracle Cloud or your own servers — so one set of keys can serve several clouds while staying in India, billed in INR.

PKCS#11, Java JCE, Microsoft CNG/KSP, KMIP and REST* — most CAs, databases and signing tools connect without code changes.

M-of-N quorum

Partition administration and key export policies need a quorum of your custodians — for example 3 of 5 — so no single person, including ours, can act alone.

Every login, key operation and policy change logged, streamed to your SIEM or our SOC and retained for CERT-In's 180 days.

HSM-wrapped backups

Key material is backed up only in wrapped form to HSM backup partitions, never as plaintext files, under the same quorum.

Multi-cloud key management

Many Indian enterprises run on more than one cloud. Keeping a master copy of each key in one HSM in Mumbai — and importing or proxying it into each cloud — gives one rotation schedule, one audit trail and one place to revoke.

Key sovereignty for regulated entities

Banks, NBFCs, insurers, market intermediaries and CAs are asked where keys live and who can reach them. A named Indian facility, your own quorum and an exportable audit log answer that directly.

The trade-off with HYOK

If the external key manager is unreachable, the cloud service cannot decrypt. HYOK needs HA, DR and low-latency links designed in — which is why we pair it with two Mumbai HSMs and a DR site.

Migration path

Moving keys is a ceremony, not a copy-paste.

Two journeys we run most often. Whether a key can move at all depends on how it was created; non-extractable keys are re-issued, not exported.

Journey A

On-prem HSM → XcellHost Cloud HSM

  1. 1InventoryEvery key, its attributes, owners, applications and expiry.
  2. 2Decide per keyWrapped transfer where the OEM and policy allow it; otherwise generate new keys and re-issue certificates.
  3. 3CeremonyPartition initialised, quorum cards issued, transfers witnessed and recorded.
  4. 4Parallel runApplications switched one at a time over private link; old HSM stays live as fallback.
  5. 5RetireOld appliances zeroised under witness; certificate of destruction kept for audit.

India compliance

Cloud HSM helps you meet what Indian regulators ask.

A cloud HSM is a control, not a compliance certificate. This is where it fits.
