    Overview

    XcellCloud is built on OpenStack, so everything you can click in the console you can also do over HTTPS. Ask the identity service (Keystone v3) for a token, read the service catalog it returns, and call the services you need: Nova for servers, Neutron for networks, subnets, routers, security groups and floating IPs, Cinder for volumes and snapshots, Glance for images and Octavia for load balancers.

    These are the standard upstream APIs, so the tools your team already uses — curl, openstacksdk, gophercloud, the OpenStack CLI, Terraform and Ansible — work against XcellCloud without plug-ins. API access is free with your XcellCloud account; you pay only for the resources you create. Your exact endpoints are shown in the XcellCloud console → API Access.

    Security · least privilege by default, data in India

    Application credentials

    Give scripts and CI their own ID and secret, scoped to one project — never a person's password.

    Least-privilege roles

    Use reader for dashboards and audits, member for automation. Add --restricted access rules where you can.

    Rotate & expire

    Set an expiry on every credential, rotate on a schedule and revoke the old one the moment the new one works.

    Never commit secrets

    Keep clouds.yaml, secure.yaml and *-openrc.sh in .gitignore; inject secrets from your CI vault.

    MFA on the console

    Turn on multi-factor sign-in for every person who can create credentials in the XcellCloud console.

    IP allow-lists

    Limit API access to your office and CI egress IPs — available on request; ask our engineers.

    TLS everywhere

    Every endpoint is HTTPS. Tokens travel only in the X-Auth-Token header — never in URLs or logs.

      Reference
      Pagination, errors and polling — the parts that bite.
      Five behaviours every OpenStack client must handle. Get these right and your automation survives real-world load.
      
    
      
      
      
        
      
      
      
      Ask for pages with limit and marker
      List calls return a page of results. Pass limit for the page size and marker = the ID of the last item you received. Nova and Neutron add a *_links array with rel: "next"; Glance returns a next URL. Stop when no next link comes back.
      • Never assume one call returns everything
      • Keep the same filters on every page
      • SDK generators page for you automatically
      
      
      Read the status code first
      CodeMeaningWhat to do
      
        
      400Bad request body or parameterFix the JSON; the message names the field
      
        
      401Token missing, expired or revokedGet a new token, then retry once
      
        
      403Your role does not allow itCheck the credential's role and access rules
      
        
      404Wrong ID, or not in your projectCheck the project scope and region
      
        
      409Conflict — resource busy or in the wrong stateWait for the current task, then retry
      
        
      413 / 429Over a rate limit or quotaBack off; honour Retry-After if sent
      
        
      5xxService-side problemRetry with exponential backoff; tell support with the request ID
      
      
      Include the X-Openstack-Request-Id response header when you contact XcellHost support — it lets us trace the call.
      
      
      Create returns fast — the work finishes later
      Most create calls return 202 Accepted (or 201 with a pending state) while the resource builds. Poll the resource until it reaches its ready state, and stop on an error state.
      
      
      Pin the behaviour you tested against
      Nova, Cinder and Octavia version their APIs inside the major version. Send a microversion header to get the fields and behaviour you expect; without it you get the minimum version. GET the service root to see the supported range.
      • OpenStack-API-Version: compute 2.79
      • OpenStack-API-Version: volume 3.60
      • Supported range: GET /v2.1/ → min_version, version
      Version numbers here are examples — check the range your endpoint reports.
      
      
      Fair use per project placeholder
      Each project has quotas (instances, vCPUs, RAM, volumes, floating IPs) and the API applies fair-use rate limits. Read your quotas through the API, and treat 413/429 as "slow down", not as failure.
      • Quotas: GET /v2.1/limits or openstack quota show
      • Back off 1 s, 2 s, 4 s… up to 60 s
      • Need higher limits? Ask XcellHost — we raise quotas on request
