01 — How serverless works
You send tokens in, you get tokens back — and the meter only runs while that happens.
No GPU to size, reserve or babysit. XcellHost keeps open models loaded on a shared, autoscaling GPU pool in Mumbai; your application calls an HTTPS endpoint and is billed for the tokens it actually uses.

    

      
A
₹ per 1M tokens
Pay per token
Input and output tokens are metered separately at the model's rate, in rupees. Embeddings bill per token, Whisper per audio minute. Top up with prepaid credits; usage draws them down.
  • INR rates · 18% GST on invoice
  • Usage by key, project and model

      
B
Autoscale, then scale to zero
Replicas are added when traffic rises and released when it falls. When no one calls, nothing runs on your account — there is no idle GPU line on your bill.
  • Bursts handled by a shared pool
  • Cold starts possible on rarely used models

      
C
https://api.openai.com/v1https://api.xcellhost.cloud/v1
OpenAI-compatible endpoint
Point the OpenAI SDK, LangChain, LlamaIndex or plain HTTP at https://api.xcellhost.cloud/v1 placeholder and change the model name. Chat completions, streaming, embeddings and transcription follow the familiar request shapes.
  • One base-URL change
  • Server-sent-event streaming

02 — Life of a request
From your app to a GPU and back — follow one request as you scroll.
Every call travels the same six stages. The diagram re-forms at each stage; the figures in it are sample values.

    

      
    
        
  1. 01Your applicationRequest
    Your code sends a chat, embedding or transcription request over HTTPS with an API key — from an app, a WhatsApp bot, a back-office job or a notebook.
    POST /v1/chat/completions
    2. 
        
  2. 02Edge · India regionGateway
    The gateway checks the key, the project's quota and rate limits, then admits the request. Over-limit calls get an HTTP 429 with a retry hint instead of silently queuing.
    Auth · quota · rate limit
    3. 
        
  3. 03Model-awareRouter
    The router reads the model name and sends the request to a replica of that model with spare capacity, preferring one that is already warm.
    Route by model · least-loaded
    4. 
        
  4. 04AutoscalingWarm pool
    Popular models stay loaded. When queues grow, more replicas start; when traffic stops, they are released. A rarely used model may need a cold start of its own.
    Scale up · scale to zero
    5. 
        
  5. 05NVIDIA GPUsInference
    Industry-standard open-source serving engines batch many users' requests together on the GPU: the prompt is read in one pass, then the answer is generated one token at a time.
    Continuous batching · L4 / RTX Pro 6000 / H200
    6. 
        
  6. 06Back to youStream & meter
    Tokens stream back as they are generated, so users see text immediately. Prompt and completion tokens are counted and drawn down from your prepaid credits in rupees.
    SSE stream · usage in INR
