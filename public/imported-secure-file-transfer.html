How zero-knowledge works

We store your files. We can't open them.

Encryption happens in your browser or app, with a key made on your device. What reaches our servers is ciphertext. Only people you share with get a way to decrypt it.

1 · Key on your device

A random AES-256 key is created for each file. It is wrapped with your own key, which never leaves the device in readable form.

2 · Encrypt, then upload

The file is encrypted and split into chunks before upload. File names and folder names are encrypted too.

3 · Ciphertext in Mumbai

Encrypted chunks are stored in XcellHost's Tier IV data centre in Mumbai, also encrypted at rest and over TLS in transit.

4 · Decrypt at the recipient

The recipient's browser fetches the chunks and decrypts them locally, after any password or verification you set.

What XcellHost can see

  • Account e-mail, plan and billing details
  • Encrypted chunk sizes and total storage used
  • Timestamps and IP addresses in the audit trail
  • That a link exists, its expiry and download count

What XcellHost cannot see

  • File contents, file names and folder names
  • Your passwords, API keys and vault notes
  • The text of your secure messages
  • Your encryption keys or recovery phrase

The trade-off, stated plainly

Because we never hold your keys, we cannot recover files if every admin loses their key and recovery phrase. Business plans add admin-held recovery keys so the company, not XcellHost, can restore access when someone leaves.

Sharing controls & audit trail

Decide how a file can be opened. Then prove what happened.

These controls are set per link, or enforced for everyone from the admin console.

Link expiry

Links stop working at a date and time you set. Admins can cap the maximum.

Download limits

Allow one download or ten. The link closes when the count is reached.

Password links

The password is part of the decryption, not just a gate. Send it on a different channel.

Recipient check

A one-time code goes to the recipient's e-mail before the file opens.

Revoke any time

Kill a link after sending. Files already downloaded stay with the recipient, so set limits early.

View-only previews

Let people read a document in the browser without a download button*.

Audit trail

Logins, uploads, shares, downloads, deletions and setting changes, with time and IP.

Export & SIEM
