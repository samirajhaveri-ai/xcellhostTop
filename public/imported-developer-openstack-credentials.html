    Overview

    Every call to XcellCloud — from the console, the OpenStack CLI, Terraform, an SDK or a plain curl — starts with Keystone, OpenStack's identity service. You prove who you are, Keystone hands back a short-lived token scoped to one project, and every other API accepts that token. People should sign in to the console with MFA. Everything else should use an application credential: an ID and secret you create for one project, with only the roles it needs and an expiry date, that you can delete in seconds without touching anyone's password. This page shows each method, generates ready-to-use clouds.yaml and openrc files in your browser, and walks through rotation and what to do if a key leaks. Credentials cost nothing — they come free with your XcellCloud account.

    Your exact endpoints are shown in the XcellCloud console → API Access. Endpoints, region and IDs on this page are examples.

    Application credentials

    Create one per job — with a role and an expiry.

    Create them in the console (Identity → Application Credentials) or with the CLI. They belong to your user and one project, carry only the roles you pick, and stop working when deleted or expired.

    shell
    # Log in first (clouds.yaml with your user, or source a password openrc)
openstack application credential create terraform-ci \
  --role member \
  --expiration 2027-01-31T00:00:00 \
  --description "GitHub Actions - web-prod" \
  --restricted

# The secret is shown ONCE. Copy it straight into your secret store.
    {
  "id": "a3f9c2e17b4d4f0e9c1d2b3a4e5f6a7b",
  "name": "terraform-ci",
  "description": "GitHub Actions - web-prod",
  "project_id": "5d2b8c3f1e4a4b6c9d0e1f2a3b4c5d6e",
  "roles": "member",
  "unrestricted": false,
  "access_rules": [],
  "expires_at": "2027-01-31T00:00:00.000000",
  "secret": "<APP_CRED_SECRET>"
}
    # Narrow a credential to specific API calls (access rules, where enabled)
openstack application credential create inventory-bot \
  --role reader \
  --expiration 2026-12-31T00:00:00 \
  --access-rules '[{"service": "compute", "method": "GET", "path": "/v2.1/servers"},
                   {"service": "compute", "method": "GET", "path": "/v2.1/servers/*"}]'

# This bot can list and read servers, and nothing else.
    openstack application credential list
openstack application credential show terraform-ci -f json
openstack application credential delete terraform-ci

# Application credentials can't be edited: to change roles or
# expiry, create a new one and delete the old one.

    Flags that matter

    • --role member — repeat for more roles; use reader for read-only jobs. Never admin.
    • --expiration in YYYY-mm-ddTHH:MM:SS. Without it the key never expires.
    • --restricted (the default) stops the key from creating more credentials. Avoid --unrestricted.
    • --access-rules limits a key to listed API calls, where enabled.
    • The secret is shown once. Lost it? Delete the credential and create another.

    Which file?

    • clouds.yaml — named clouds; switch with --os-cloud or OS_CLOUD. Can be shared once secrets move out.
    • secure.yaml — only the secrets, merged in at run time. Keep it private.
    • openrc — exports OS_* variables for the current shell; the password version prompts instead of storing.
    • chmod 600 all three and add them to .gitignore.
    Keystone v3 tokens

    Credential in, scoped token out — valid for a limited time.

    POST /v3/auth/tokens returns the token in the X-Subject-Token header and the service catalog in the body. Send it as X-Auth-Token on every other call. Application-credential tokens are always scoped to the credential's project.

    shell
    # 1. Ask Keystone for a token (application credential)
cat > token-req.json <<'EOF'
{
  "auth": {
    "identity": {
      "methods": ["application_credential"],
      "application_credential": {
        "id": "<APP_CRED_ID>",
        "secret": "<APP_CRED_SECRET>"
      }
    }
  }
}
EOF

TOKEN=$(curl -s -i -X POST https://api.xcellhost.cloud:5000/v3/auth/tokens \
  -H "Content-Type: application/json" -d @token-req.json \
  | awk 'tolower($1)=="x-subject-token:" {print $2}' | tr -d '\r')
rm token-req.json

# 2. Use it on any API in the catalog
curl -s -H "X-Auth-Token: $TOKEN" https://api.xcellhost.cloud:5000/v3/auth/catalog

# 3. Revoke it when the job is done
curl -s -X DELETE https://api.xcellhost.cloud:5000/v3/auth/tokens \
  -H "X-Auth-Token: $TOKEN" -H "X-Subject-Token: $TOKEN"

    Token facts

    • Lifetime: read expires in the response — commonly one hour on OpenStack clouds. SDKs refresh tokens for you.
    • Scope: project-scoped tokens act only inside that project; password logins choose the project in scope.
    • Bearer: anyone holding a token can use it until it expires — never log it.
    • Revoke: DELETE /v3/auth/tokens or openstack token revoke. Deleting a credential invalidates its tokens.

    Roles & project scoping

    Give each key the smallest role — on one project.

    Keystone's default roles nest: admin includes member, which includes reader. A credential can only hold roles its owner already has on that project.

    Storing secrets & rotation

    Keep secrets in a vault — and rotate without downtime.

    Secrets belong in a secret manager or your CI's protected variables, never in code, chat or tickets. Rotation is four commands.

    shell
    # HashiCorp Vault (KV v2): store once, read at deploy time
vault kv put secret/xcellcloud/terraform-ci \
  id="<APP_CRED_ID>" secret="<APP_CRED_SECRET>"

export OS_APPLICATION_CREDENTIAL_ID=$(vault kv get -field=id secret/xcellcloud/terraform-ci)
export OS_APPLICATION_CREDENTIAL_SECRET=$(vault kv get -field=secret secret/xcellcloud/terraform-ci)
    # GitHub Actions: repository or environment secrets
gh secret set OS_APPLICATION_CREDENTIAL_ID --env production
gh secret set OS_APPLICATION_CREDENTIAL_SECRET --env production
# (gh prompts for the value, so it never lands in shell history)

    If a credential leaks

    Revoke first, investigate second — in this order.

    A key pushed to a public repository can be found by scanners within minutes. Speed matters more than perfection.

    1Delete the credential

    openstack application credential delete <name> — or ec2 credentials delete. Its tokens stop working.

    minute 0
    2Call XcellHost 24×7

    +91 22 6711 1555 — we help check the project and lock things down.

    minute 5
    3Check what changed

    New servers, keypairs, security-group rules, floating IPs, users — openstack server list --long.

    first hour
    4Purge it from Git

    Rewrite history (e.g. git filter-repo), then rotate anything else in the same file.

    same day
    5Issue a new key

    Smallest role, short expiry, stored in your secret manager.

    same day
    6Assess reporting duties

    If personal data may be affected: DPDP Act breach intimation and CERT-In's 6-hour incident reporting.

    within 6 h

    India note: CERT-In's April 2022 directions require reporting specified cyber incidents within 6 hours, and the DPDP Act requires intimating personal-data breaches to the Data Protection Board and affected people. This page is guidance, not legal advice — check with your counsel.
