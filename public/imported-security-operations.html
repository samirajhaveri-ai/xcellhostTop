    Operating model

    ITIL 4 practices, written as runbooks — so the 2 a.m. response matches the 2 p.m. one.

    Every alert enters the same loop. Repeat work is automated or pushed to the earliest level that can safely handle it (shift-left), and every major incident ends in a problem record.

    Monitoring & event management

    Sources onboarded, use cases mapped to MITRE ATT&CK, noise tuned weekly so analysts see fewer, better alerts.

    Incident management

    Triage, severity P1–P4, investigation and containment under pre-approved runbooks; you are called for business decisions.

    Problem management

    Every P1 and repeated P2 gets a root-cause review and a fix: a rule, a hardening change or a training item.

    Change enablement

    Firewall rules, blocklists and policy changes go through approval with rollback — standard changes pre-approved.

    Service requests

    Allow-listing, user unlocks, access reviews and report requests through one portal and WhatsApp/phone line.

    Shift-left automation

    Enrichment, IP/domain reputation, user lookups and containment steps automated so L1 can act in minutes.
