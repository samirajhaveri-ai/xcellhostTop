Overview

CloudOps is how a cloud gets run, not just built.

Migration ends on a date. Operations never does. CloudOps is the set of practices, tools and people that keep every cloud estate healthy, secure and affordable after go-live.

Most Indian businesses now run a mix: a hyperscaler for new applications, Microsoft 365 and Azure for the workplace, and a private cloud for ERP or regulated data. Each brings its own console, alerts, patch cycle and invoice. Without one operating model, changes go in by hand, alerts are ignored, nobody owns the bill and audit evidence is gathered the night before.

XcellHost CloudOps replaces that with a single loop: infrastructure defined as code, observed against service level objectives, incidents, problems and changes handled under ITIL 4 practices, patching, backup and capacity on a calendar, and spend reviewed every month using the FinOps Inform → Optimize → Operate cycle. Our Mumbai NOC and SOC run it around the clock.

Looking for the managed-service contract detail — RACI, SLA targets and per-cloud scope? See Managed Cloud Operations. This page explains the CloudOps model and lets you size it.

    Formula, assumptions & sources
    1. Waste = spend × idle share × 60–90% (assumption: not every oversized resource can be cut at once).
    2. Scheduling = (spend − waste) × non-prod share × (168 − hours on) ÷ 168 × 70–100% (assumption: some non-prod must stay up).
    3. Commitments = remaining production spend × eligible share × (1 − covered share) × discount range. Range used: 20% to 72% × 0.6. Published ceilings: AWS Savings Plans up to 72% off On-Demand; Azure Reservations up to 72% on VMs and savings plan for compute up to 65%; Google Cloud resource-based CUDs up to 55% (70% memory-optimised). Real discounts depend on term, payment and instance family.

    Sources: AWS whitepaper "Cost optimization — reservation models" (Savings Plans); Microsoft Azure Reservations pricing page; Google Cloud "Committed use discounts overview" — all read November 2026. Not a quote; a billing-data review gives the real figure.

        FAQ

        CloudOps, answered.

        CloudOps — cloud operations — is the practice of running cloud infrastructure day to day: provisioning it as code, monitoring and observing it, handling incidents, problems and changes, patching, backup, capacity, cost management and reporting. It is what keeps a cloud reliable and affordable after migration.

        Managed Cloud Operations is the service contract: scope per cloud, RACI and SLA targets. This CloudOps page explains the operating model behind it — IaC, SLOs, FinOps, maturity — and lets you size a package. The tier prices are the same.

        Amazon Web Services, Microsoft Azure, Google Cloud, Oracle Cloud Infrastructure and XcellCloud, XcellHost's private and public cloud in our Mumbai Tier IV data centre — plus VMware, OpenStack and Proxmox estates. Several can run on one desk and one report.

        An SLO is an internal reliability target for a service, such as 99.9% of requests succeeding over 30 days. An SLA is the contractual commitment, with remedies if it is missed. SLOs are usually stricter than SLAs, so the team reacts before the contract is at risk.

        Over a 30-day window, 99.9% allows 43.2 minutes; 99.95% allows 21.6 minutes; 99.99% allows 4.32 minutes (about 4 minutes 19 seconds). Over a 365-day year, 99.9% allows about 8 hours 46 minutes. The calculator above does the maths for any window.

        We follow the FinOps Foundation's three phases. Inform: tag, allocate and show spend by team. Optimize: remove idle resources, right-size and plan commitments. Operate: set budgets, alerts and policies so savings stick. Results are reported in rupees every month.

        Yes. Incident, problem, change enablement, monitoring and event management, and service level management follow ITIL 4 practices inside XcellHost's ISO 20000-1 certified IT service management system. Records are kept in your ITSM tool or ours.

        No. Normal changes are approved by you. Low-risk repeatable changes, such as a scale-out within agreed limits, can be pre-approved as standard changes. Infrastructure-as-code changes are reviewed as pull requests before apply, and every action is logged.

        Essential is ₹14,999* and Professional ₹39,999* per cloud estate per month, with ₹999* per extra resource and ₹24,999* one-time onboarding. Enterprise is on quote. All indicative, excl. 18% GST; cloud usage is billed at actuals.
