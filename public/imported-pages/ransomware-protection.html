The problem

Encryption is the last step, not the first. Most attacks run for days before it.

A ransomware attack is a sequence. Each step leaves traces and each step can be blocked. Here it is in plain language, mapped to MITRE ATT&CK tactics and techniques — tap a step.

Technique IDs from MITRE ATT&CK (attack.mitre.org), checked November 2026. We describe what defenders see, not how attacks are carried out.

How attackers got in, per CERT-In's 2024 ransomware report

The report names exposed services, not exotic exploits. Every item below is a configuration you can check this week.

  • Remote Desktop (RDP) open to the internet, brute-forced or hit with stolen passwords
  • Microsoft SQL servers exposed and brute-forced
  • Internet-reachable VMware ESXi and vCenter consoles with weak access rules
  • Public cloud storage misconfigurations, weak IAM policies and compromised credentials
  • Exposed NAS devices, Redis servers and firewall management consoles
  • Unpatched vulnerabilities and backdoors left by incomplete clean-up
Warning signs

The signals arrive early. Someone has to be watching.

What our SOC alerts on, grouped by how long they usually come before encryption. Any one of these deserves a call.

Weeks before
  • New admin accounts nobody requested
  • VPN or cloud sign-ins from unusual countries or impossible travel
  • Remote-access tools IT didn't install
  • Security alerts quietly switched off or excluded
Days before
  • Network scanning from a user laptop
  • Credential-dumping alerts on servers
  • Large uploads to cloud storage at odd hours
  • Backup jobs failing, shortened or deleted
Minutes before
  • Volume shadow copies deleted
  • Antivirus, EDR or backup services stopped
  • Mass file renames with a new extension
  • Ransom-note files appearing in many folders
Layered defence

Prevent → Detect → Respond → Recover.

No single product stops ransomware. Four layers, each assuming the one before it failed.

01

Prevent

Shrink the ways in.

  • Patching for VPNs, firewalls, servers and apps
  • MFA on remote access, email and admins
  • Privileged access with just-in-time admin
  • Email security and awareness training
  • Microsegmentation around servers and backups
02

Detect

See the steps before encryption.

  • EDR: Defender, Scrutiny* or SentinelOne*
  • NDR for scanning and east-west traffic
  • UEBA for unusual account behaviour
  • NG-SIEM with 180-day logs in India
03

Respond

Contain in minutes, not hours.

  • 24×7 SOC that can isolate hosts
  • Case management with CERT-In timers
  • Forensics & incident response
  • MXDR for Microsoft
04

Recover

Restore clean, in the right order.

  • Immutable Acronis* backups with warranty
  • Veeam* or Commvault* operations
  • Entra ID backup for identities
  • Cloud DR with tested runbooks

    DPDP Act, 2023 & Rules, 2025

    If personal data is affected: intimation to the Data Protection Board and each affected person without delay, and a detailed report to the Board within 72 hours. Core duties apply from 13 May 2027. DPDP platform →

    RBI & SEBI

    Regulated entities also report under their regulator's directions — urban co-operative banks, for example, on RBI's DAKSH platform within six hours. SEBI's CSCRF (20 August 2024) expects SOC monitoring and tested recovery.

    Report the crime

    Ransomware is extortion. File with the police or the National Cyber Crime Reporting Portal (cybercrime.gov.in); call 1930 if money has moved.

    On paying

    We don't negotiate with attackers. CERT-In's report advises verifying extortion claims with evidence before any payment; decide with your counsel and insurer. Paying does not guarantee a working decryptor.

    FAQ

    Ransomware, answered.

    Malicious software, run by a criminal group, that encrypts your files and systems so they can't be used, then demands payment for a decryption key. Most groups now also copy data out first and threaten to publish it, so a restore alone doesn't end the extortion. The encryption is the final step of an intrusion that usually began days or weeks earlier.

    No. Attackers often log in with stolen passwords and use normal admin tools, which signature antivirus won't flag.     The storage refuses changes or deletion until a retention period ends — even from an administrator account. That matters because attackers look for backup consoles and delete recovery points first (ATT&CK T1490). We keep the immutable copy in India and test restores from it every quarter.
