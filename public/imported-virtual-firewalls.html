      How inspection works

      Follow one packet through the firewall — six checks in milliseconds.

      Scroll to follow an inbound HTTPS request to your app. The same thirty cells of a packet rearrange as each layer looks at a different part of it.

      ArriveDecryptIdentifyInspectFilterLog
      Step 1 of 6Arrive · L3/L4 rulessample
      443/tcp from 49.207.x.x · allowed by rule #1first matching rule wins · everything else denied
      1. 01Layer 3 / 4Arrive — stateful rules

        Source, destination, port and protocol are checked against your rule list, top to bottom. The first match decides; anything not explicitly allowed is dropped. Return traffic for an allowed session is tracked and let back in automatically.

        Stateful · default deny
      2. 02Encrypted trafficDecrypt — TLS inspection

        Most attacks now arrive inside HTTPS. For the destinations you choose, the firewall terminates TLS, inspects the clear-text request and re-encrypts it. Banking, health and other sensitive categories can be excluded by policy.

        Decrypt · inspect · re-encrypt
      3. 03Layer 7Identify — application control

        Deep packet inspection names the application behind the traffic — web, a SaaS tool, SSH, a torrent client or an anonymising proxy — so policy can say “allow Microsoft 365, block BitTorrent” regardless of port.

        Apps · users · groups
      4. 04Intrusion preventionInspect — IPS / IDS

        The payload is compared with exploit signatures and behaviour rules: SQL injection, remote code execution, brute force, protocol abuse. In prevention mode the packet is dropped; in detection mode it is logged and alerted.

        Signatures · rate rules
      5. 05ContentFilter — web & anti-malware

        URLs are checked against category and reputation lists and files against anti-malware engines. Known malware, phishing and command-and-control destinations are blocked in both directions — inbound downloads and outbound call-homes.

        URL categories · file scanning
      6. 06Every decisionLog — and respond

        Each allow and deny is logged with time, source, rule and reason, kept in India for 180 days and streamed to your SIEM. With a managed plan, XcellHost's SOC watches the alerts and changes rules when something needs blocking.

        SIEM · CERT-In · SOC
