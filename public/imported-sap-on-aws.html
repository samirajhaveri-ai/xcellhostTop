    Overview

    Most Indian SAP estates still sit in a server room or a co-location rack: ageing hardware, a refresh bill every few years, a DR site that is rarely tested and a small team that keeps Basis running on goodwill. With SAP ECC 6.0 mainstream maintenance ending at the end of 2027, the move to S/4HANA is now a board question.             Frequently Asked Questions

            Per SAP's published maintenance strategy, mainstream maintenance for SAP ECC 6.0 (EHP 6–8) ends on 31 December 2027. SAP offers optional extended maintenance to the end of 2030 at an additional fee. Most companies use the time to move to S/4HANA — and moving ECC to AWS first is a common way to retire ageing hardware while the conversion is planned.

            Production normally runs in AWS Asia Pacific (Mumbai) across two availability zones, with a disaster-recovery copy in AWS Asia Pacific (Hyderabad). Both regions are in India, which helps with data-localisation expectations.

            Yes. SAP HANA must run on SAP-certified infrastructure; AWS offers certified memory-optimised families such as X2 and X1 and the u-series High Memory instances for the largest systems, along with certified smaller sizes. We confirm your size against the current SAP certification list during the assessment.

            Brownfield (system conversion) keeps your history and custom code and is usually fastest; greenfield re-implements on standard S/4HANA processes; selective data transition moves chosen company codes or years. The readiness assessment looks at custom code, data volume, add-ons and your downtime window before we recommend one.

            RISE with SAP is SAP's subscription bundle and is available on AWS. If you choose RISE, SAP runs the core infrastructure; XcellHost can still help with the assessment, migration planning, integrations, non-SAP systems and day-to-day support around it. If you bring your own licences, we run the full stack on AWS for you.

            Primary and secondary HANA databases run in different Mumbai availability zones with synchronous HANA system replication, and cluster software moves the service to the secondary automatically if the primary fails. Central services are protected with an enqueue replication server, and application servers run in both zones.

            HANA data and log backups go to object storage — using AWS Backint Agent where it fits — with retention set to your policy. For DR, an asynchronous HANA replica and standby application server run in Hyderabad. DR-as-a-service is quoted per landscape, and we run drills on an agreed schedule.

            24×7 monitoring, kernel and support-package patching, transports, user and role administration support, HANA backup checks, performance tuning, HA/DR tests, OS patching and monthly reports, with phone and WhatsApp escalation. Functional consulting (FI, SD, MM and so on) is scoped separately.

            AWS compute, storage and network are billed at actuals through XcellHost on an INR invoice with GST, alongside our service fees. We advise on savings plans, reserved capacity and right-sizing each month; commitment purchases are always your decision.

            Yes. We help connect SAP to the GST Invoice Registration Portal and e-way bill system through your GSP/ASP, and to banking, payroll and portal interfaces over secure links — then monitor those interfaces as part of Basis.

            A rehost of a mid-size ECC landscape is often a matter of weeks; an S/4HANA conversion or greenfield programme typically runs several months including testing. The countdown tool above shows illustrative timelines; you get a dated plan after the assessment.
