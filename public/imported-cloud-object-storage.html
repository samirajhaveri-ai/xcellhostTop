01
What object storage is

A file, its facts and a key. That is an object.

Object storage keeps each file whole, with its metadata, under a key in a bucket. You reach it over HTTPS with the S3 API — no share to mount, no volume to resize, no file server to patch.

s3://acme-tally/fy26/books.zipSample
BlockA disk on one server

Databases and OS volumes. Sized in advance, snapshot-protected.

FileA mounted share

Team folders. Grows with the NAS; permissions per folder.

ObjectHTTPS + S3 API

Backups, media, logs, datasets. Grows as you write; billed per TB actually stored.

06
Object Lock · WORM

Write once, read many. Delete only when the date says so.

On Bucket Plus and Replicated Plus, each object version can carry a retain-until date. Until then it can't be overwritten or deleted. Object Lock must be switched on when the bucket is created.

GovernanceLocked for most keys

A key with explicit bypass permission can still remove the lock. Use it to test retention before committing.

ComplianceNobody can shorten it

No key, admin or support ticket — including XcellHost's — can delete the version early. The date can only move later.

Legal holdOn until switched off

A flag with no date, for investigations and disputes. Needs its own permission to set or clear.

    Data residency · DPDP · CERT-In

    Three dates that shape how Indian companies store data.

    General information as of 16 Nov 2026, not legal advice. The regulator's current text prevails.

    1. 28 Apr 2022CERT-In directions under Section 70B(6), IT Act

      Service providers, intermediaries, data centres and body corporates keep logs of all ICT systems securely for a rolling 180 days within Indian jurisdiction, and report specified incidents within 6 hours.

    2. 13 Nov 2025DPDP Rules, 2025 notified

      MeitY notified the Rules under the Digital Personal Data Protection Act, 2023 with a phased start. Consent Manager provisions follow after 12 months (13 Nov 2026).

    3. 13 May 2027Core Data Fiduciary duties apply

      Reasonable security safeguards — including keeping logs for breach detection for at least one year — breach intimation, erasure when the purpose is served, and retention rules for specified purposes.

    ObligationBucket setting that answers it
    Data in IndiaBuckets in mumbai-1; nothing copied abroad unless you set it up
    CERT-In 180-day logsLifecycle: expire logs/ after 181 days; optional 180-day compliance lock
    DPDP: one-year breach-detection logsSeparate audit/ prefix or bucket kept 365+ days
    Reasonable security safeguardsAES-256 at rest, TLS 1.3, scoped keys per app, private buckets
    Erase once purpose is servedLifecycle expiry by prefix and age; noncurrent-version expiry
    Who accessed whatAudit trail on Replicated Plus; access logs on request*

    Lock versus erasure. A compliance-mode lock stops deletion — including a valid erasure request — until its date. Lock backups and logs for the period a law or your policy needs, not "forever".

    Operated under ISO 27001, 27017, 27018 and 20000-1 and SOC 2 Type I & II controls; MeitY empanelled — see certifications, the DPDP compliance platform and NG-SIEM for log collection. Sector rules (RBI, SEBI, IRDAI) can add their own retention periods; see BFSI Cloud.
