Overview

A digital signature on everything you ship, so users know it's really yours.

A code signing certificate lets you put a digital signature on executables, installers, drivers, scripts and macros. The signature does two jobs: it names you as the publisher after a certificate authority has checked who you are, and it seals the file — change a single byte after signing and the signature no longer verifies. Windows, browsers and antivirus tools read that signature before they decide how loudly to warn your users.

There are two assurance levels. OV (organisation-validated) is open to registered businesses and to individual developers. EV (extended validation) is for organisations only, carries the strictest vetting and is required for kernel-mode drivers. Since 2023 every private key must live on certified hardware, so XcellHost ships a FIPS token within India or sets the certificate up on your existing HSM — and prepares your MCA, GST or Udyam paperwork so validation doesn't stall.

How it works

Hash it, sign it on the token, verify it on install.

Code signing never encrypts your software. It fingerprints the file, locks that fingerprint with a key only you hold, and lets every user's computer check both.

01 · Hash
9f2c7a01e4b83dc5

Your build is fingerprinted

The signing tool runs the finished file through SHA-256. The result is a short digest that changes completely if even one byte of the file changes.

  • SHA-256 digest of the whole file
  • Runs on your build machine or CI
  • Your source code is never sent anywhere
02 · Sign on the token

The digest is signed on hardware

The digest is sent to your FIPS 140-2 token or HSM, which signs it with your private key. The key never leaves the device — that's the rule since June 2023.

  • 3072-bit RSA or ECC key
  • Token PIN or HSM policy required
  • Trusted timestamp added (RFC 3161)
03 · Verify on install
Unknown publisherYour Company Pvt Ltd

Every user's PC checks it

On download and install, Windows re-computes the digest, checks it against your signature and walks the chain to Sectigo's root. Match: your name. Mismatch: a hard warning.

  • Publisher name shown, not "Unknown"
  • Tampered files fail instantly
  • Timestamp keeps old builds valid

      Policy changes

      Three rule changes every publisher should know.

      Code signing rules are set by the CA/Browser Forum and by Microsoft. Here is what changed, and what it means when you buy today.

      2023202420252026
      Today
      June 2023 · CA/B Forum

      Keys must live on hardware

      Private keys for OV and EV code signing must be generated and stored on a FIPS 140-2 Level 2 or Common Criteria EAL4+ device — a USB token or an HSM. Downloadable .pfx files are no longer issued.

      For you: choose token delivery or your HSM at checkout.
      March 2024 · Microsoft

      EV no longer skips SmartScreen

      SmartScreen stopped giving EV-signed files an instant pass. EV still carries the highest assurance, but every new certificate builds reputation as clean downloads accumulate — same as OV.

      For you: plan for reputation to build over the first weeks of downloads.
      February 2026 · CA/B Forum

      One-year certificates

      New code signing certificates are issued for at most about a year. HSM-based orders can be bought for up to three years, with a fresh certificate reissued each year.

      For you: token orders are 1-year; 2–3 years need your HSM.
