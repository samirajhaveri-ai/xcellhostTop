01
CSR generator
Creates a new private key and a PKCS#10 certificate signing request with Subject Alternative Names. The key is made by your browser and stays here.

          
For production servers, generate the key on the server that will use it. That way the private key never touches another machine. Use this page when that is not practical, then save the key straight to the server and delete any local copy. The OpenSSL command below does the same job on the server.

02
CSR decoder
Check a CSR before you send it: subject, SANs, key size, signature algorithm, and whether the signature verifies.

          

            
            

          

          

        


        
        

          
03
Certificate decoder & chain check
Paste one certificate, a full chain or a .p7b bundle. You get validity and days left, SANs, key, issuer, fingerprints, and hints on chain order and missing intermediates.

          
Live checks from a server are coming soon. A browser page can't open a raw TLS connection to your site, so a live checker needs a server. Until we release it, paste what your server sends (for example, the output of openssl s_client -connect example.in:443 -showcerts), or ask XcellHost support to run the check for you.

          

            
            

            

          

          

        


        
        

          
04
Format converter
PEM ⇄ DER, a PEM chain → PKCS#7 (.p7b), a .p7b → PEM, and RSA or EC keys between PKCS#1/SEC1 and PKCS#8. PFX needs a password and a private key, so for PFX we build the OpenSSL command for you to run locally.

          

            
            

          

          

          

            
OpenSSL command builder

05
Key matcher
Does this certificate belong to this private key, and was it issued from this CSR? We compare the SHA-256 of each public key (SPKI). For RSA we also show the modulus MD5 that the usual OpenSSL one-liner prints.

          

            

            

            

          

          

          
Any two are enough. Accepts PKCS#8, traditional RSA (PKCS#1) and EC (SEC1) keys. Encrypted keys are refused: decrypt them on your own machine first.

CA/Browser Forum ballot SC-081v3 cuts the maximum life of a public TLS certificate in three steps. The certificate decoder flags server certificates issued after 15 March 2026 that last longer than 200 days.

FAQ
SSL tools, answered.

    
The key is created by your browser's built-in WebCrypto API and is never sent anywhere; this page has no upload endpoint. The risk is on your side: the key exists on the computer you used. For production servers, the safer habit is to run the OpenSSL command we show on the server itself and paste only the CSR into your order.


RSA 2048 works with every client and every public CA. ECDSA P-256 gives smaller certificates and faster handshakes, and current browsers all support it. Pick RSA 3072 or 4096 only if a policy asks for it: larger keys slow TLS handshakes. Public CAs require at least RSA 2048 (CA/Browser Forum Baseline Requirements §6.1.5, not re-verified for this page).


Browsers match the hostname against the Subject Alternative Names only and ignore the common name. Most CAs copy the CN into the SANs for you, but if your CSR names only www.example.in in the CN and something else in the SANs, check the names on your order. Our generator always repeats the CN in the SAN list.


Not yet. A web page can't open a raw TLS connection to another server, so a live checker needs a server-side component, which is coming soon. For now, paste the chain your server sends (for example from openssl s_client -connect yoursite.in:443 -showcerts) into the certificate decoder, or ask XcellHost support to run the check for you.


Your server certificate was signed by an intermediate CA that is not in the text you pasted. If your server also leaves it out, some browsers and most apps and API clients will fail with an incomplete-chain error. Install the CA bundle your certificate authority sent. The decoder shows the "CA issuers" download address when the certificate carries one.


A PFX bundles the private key with the certificate behind a password, so we don't build it in the browser. Open the converter, pick "PEM certificate + key → PFX" in the command builder and run the command on the machine that holds the key. If Windows Server 2016 or older Java refuses the file, tick "older Windows / Java" to add -legacy.
Run all three files through the key matcher. If the certificate's public key differs from the key's, the certificate was issued for a different CSR. Look for the key made alongside that CSR. If it is lost, generate a new CSR and ask your CA to re-key (reissue) the certificate; that is usually free within the term.


The SHA-256 of the public key (SPKI) works for RSA and ECDSA keys and is what we compare. The modulus MD5 is the value the long-standing support one-liner openssl x509 -noout -modulus -in cert.crt | openssl md5 prints, shown so you can compare with notes from other tools. MD5 is used here only as a checksum, not for security.
