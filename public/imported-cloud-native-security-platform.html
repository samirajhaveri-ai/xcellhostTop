What a CNAPP is

Ten security tools, one view — from the first commit to the running pod.

Cloud-native estates are built from code, infrastructure templates, container images, Kubernetes clusters and cloud services — and, increasingly, AI models. Each layer used to have its own scanner and its own alert queue. A cloud-native application protection platform (CNAPP) brings posture, identity, vulnerability and runtime protection into one inventory, so one misconfiguration, one vulnerable package and one over-privileged role can be seen as the single attack path they form.

XcellSecure CNAPP is that platform, operated for you. We deploy a leading zero-trust CNAPP partner platform* agentless across your cloud accounts and with lightweight agents on clusters and hosts, connect it to your repositories and CI, and run the triage and remediation from our 24×7 Mumbai SOC. It runs as SaaS, inside your own cloud account, on XcellHost private cloud or fully air-gapped. Billed in INR.

Runtime zero trust

Allow what you expect. Block everything else, before it runs.

Most runtime tools alert after the fact and then kill the process. Kernel-level enforcement denies the action as it is attempted.

Same event, two approaches

    Audit mode records every action outside the allow-list without stopping it — this is how we learn normal behaviour for two to four weeks* before enforcing.

    payments-allow.yamlsample policy
    # generic illustration, not a vendor schema
kind: RuntimePolicy
selector:   app=payments, ns=prod
action:     Audit   # everything not allowed
allow:
  process:  /usr/bin/java, /bin/healthcheck
  files:    /app/** (read), /tmp/** (write)
  network:  tcp → payments-db:5432
            tcp → upi-gateway:443
  caps:     none
    eBPF visibility

    Process, file and network events read from the kernel with low overhead — no sidecars.

    LSM enforcement

    Policies applied through Linux Security Modules (AppArmor, SELinux or BPF-LSM), so the denied call never completes.

    Auto-generated policies

    Baselines learned from observed behaviour, reviewed by our engineers, then switched to enforce.

    Alerts to the SOC

    Every deny is an event in your SIEM and a case for the Mumbai SOC, with the pod, image and owner attached.

        Frequently Asked Questions

        A cloud-native application protection platform combines cloud and Kubernetes posture management, identity entitlement management, vulnerability scanning and workload runtime protection in one platform with one asset inventory, so risks in code, cloud, clusters and containers can be correlated and fixed together.

        CSPM checks cloud configuration, such as public storage or open ports. KSPM does the same for Kubernetes clusters and workloads. CIEM looks at who and what can access which resources. CWPP protects the running workload — hosts, VMs, containers — with vulnerability scanning and runtime controls.

        Post-exploit tools detect suspicious activity and then kill the process, so the first action has already happened. Inline mitigation uses Linux Security Modules to deny the system call as it is made, so a disallowed process, file write or connection never completes.

        Cloud posture, identity and VM vulnerability scanning can run agentless through read-only cloud roles. Runtime protection and Kubernetes micro-segmentation need a lightweight agent, usually a DaemonSet on each node, built on eBPF. Private, firewalled or edge nodes also use the agent.

        Yes. Besides SaaS, the control plane can run in your own cloud account, on a dedicated cluster in XcellHost's Mumbai Tier IV data centre, or on-prem and air-gapped with offline updates. India-region SaaS hosting is confirmed per quotation*.

        AWS, Azure, Google Cloud and Oracle Cloud, plus VMware, OpenStack, Nutanix and bare metal. Kubernetes coverage includes EKS, AKS, GKE, OKE, Red Hat OpenShift, Rancher and upstream clusters, including edge and 5G clusters.

        By combining severity with context: whether a public exploit exists, whether the asset is reachable from the internet, whether the vulnerable package is actually loaded at runtime, and what data and identities are within reach. Try the prioritisation demo above.

        Discovery of AI services, models, notebooks and vector stores in your clouds; posture checks on their access and data; model and dataset scanning; and a prompt firewall that blocks prompt injection and redacts secrets and personal data in prompts and responses.

        It produces the evidence those frameworks ask for — inventory, secure configuration, vulnerability management, access review, monitoring and logs kept in India. It does not make you compliant on its own; we map checks to your control framework during onboarding.
